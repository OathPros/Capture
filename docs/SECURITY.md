# Preview security and privacy

Capture is explicitly started, visible and local-only. It never installs a keyboard hook or reads UIA ValuePattern. Screenshot buffering stops on pause/finish; selected screenshots are stored under the user's LocalAppData. A password control identified by UIA suppresses that click, but surrounding screen content may still contain secrets. Process exclusions are case-insensitive substrings of foreground/clicked process names. Private-window detection is not implemented. Use synthetic data; opaque redaction and permanent pixel application are available; verify results before sharing.

Screenshots now use the native asset.read bridge rather than a second virtual-host origin. Only the current project and declared asset IDs are accepted; no arbitrary file paths are exposed.

The low-level mouse callback only copies position/monotonic time into a bounded channel and calls the next hook. No disk/UIA/screenshots/network run in it. A separate MTA worker handles accessibility; screenshots use a separate sampler. A hung provider requires process restart; saved drafts are retained.

WebView2 loads only the bundled capture.local page with a strict CSP. Navigation, downloads, new windows and permissions are rejected. Each host message checks origin/version/allowlist and data size. Project asset identity cannot be changed through editor saves. File dialogs select import/export paths; there is no arbitrary file or shell bridge. Project data is treated as plain text.

Imports validate relative paths, duplicate entries, total/archive entry sizes, count, schema, annotation bounds, image checksums and PNG headers/dimensions. Extract only referenced assets into a new GUID project folder; roll back failed imports. Projects, exports and WebView2 data are not encrypted by this app. Treat portable packages as containing original screenshots. Existing external exports/backups are not removed by deleting or editing a project.

No release signing has been configured. No server/SSO/Halo/telemetry integration is included. Follow enterprise application approval before deployment. Do not use this preview for institutional personal data until interactive tests and privacy/security review are complete.

Document exports validate source image dimensions/checksums before rasterizing highlight copies. DOCX is generated as Open XML without macros or external image relationships. Markdown escapes user text and bundles relative image assets. HTML escapes all user fields, embeds PNG bytes as data URLs, permits only inline styling/data images through CSP, and contains no script or external resources. Export to a temporary sibling file and replace the destination only after success. These formats retain visible screenshot content; highlight outlines are not redaction.

Schema 1.1 permits only known shape kinds, bounded normalized geometry, hex colours, limited text/font/stroke/blur properties and validated crop regions. User text is rendered as text, never HTML. Blur/redaction remain preview layers until explicit permanent application. That transaction creates a new sanitized PNG, saves metadata/cleanup intent before deleting the original, updates every step sharing the asset, and clears undo history. Exports reject pending layers or unfinished cleanup; raw originals cannot enter a portable export through those states. Ordinary crop retains originals by design and is not a privacy operation.

Clipboard actions are explicit, constrained document projections. HTML code is Unicode source text; Word content is RTF with escaped text and hex-encoded PNGs, plus Unicode text fallback. No arbitrary RTF/HTML control syntax is accepted from guide text. Both use the same privacy guards as file export and create no temporary document/image files. Windows clipboard history/sync is governed by the user's OS settings; copied content may be retained there. Cut strips retain originals by design and are not redaction. Static UIA field labels or whitelisted semantic identifier tokens may name Edit controls; Edit.Name and ValuePattern are not read.
